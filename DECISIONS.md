# Decisions

- **Project:** buyer-first pre-checkout purchase review for shoppers in Mexico; the governing specification is [docs/PACKET.md](docs/PACKET.md).
- **Stack:** dependency-free static HTML, CSS, and JavaScript plus a Vercel Node serverless function. Gemini is called with direct server-side `fetch`; `GEMINI_API_KEY` is read only by the function.
- **Privacy:** no accounts, database, or history. Form criteria are bounded, image type/signature/size and request size are validated, and screenshot bytes are sent only for the active analysis request. The app does not log or persist image contents.
- **Honest status:** without `GEMINI_API_KEY`, the endpoint explicitly returns DEMO mode and does not analyze the screenshot. With a key, Gemini vision can extract visible screenshot text; extracted claims are labeled advertised/unverified, missing fields unknown, and the output is not a recommendation or independent verification.
- **Upload:** PNG/JPEG/WebP only, at most 3 MiB, checked in browser and server; the server also validates file signatures. No original screenshot is saved.
- **Cost handling:** missing delivery remains unknown and the displayed amount is explicitly incomplete; the app does not infer shipping, exclusions, return costs, or protections.
- **Evidence cards:** buyer-entered amounts are labeled unverified and sourced to buyer input; screenshot text is labeled advertised and sourced to the supplied screenshot; local arithmetic is labeled as a calculation, not as verified evidence. Every card shows the check date. Missing return terms, exclusions, fees, claim routes, fit, and quality remain unknown.
- **Correction workflow:** correction requests are editable, copyable local drafts held only in the current page. They are explicitly not submitted and not human-reviewed; there is no backend or stored personal information.
- **Mechanical test pass:** documented in [docs/TEST_LOG.md](docs/TEST_LOG.md). Fixed a summary mismatch when shipping is known but product price is missing; the main total now shows the known partial amount.
- **Persona findings:** owner-reported five-screen synthetic walkthrough with Lucía (38, Mexico City) identified ambiguity around local corrections, “SUSTENTADO” totals, and what to do when waiting. The record and limits are in [docs/PERSONA_LOG.md](PERSONA_LOG.md).
- **Persona-driven copy:** correction is explicitly a local unsent/unreviewed draft; totals are labeled local calculations, not verification, and disclose unknown additional charges; waiting explains specific information to check and update. Local browser smoke checks passed.
- **Synthetic-persona retest:** Lucía confirmed clearer calculation labels and understood correction drafts are not submitted; she still needed clearer wait steps, a place to enter return terms, and nontechnical analysis availability language. See [docs/PERSONA_LOG.md](PERSONA_LOG.md).
- **Final UI changes:** Wait now provides numbered actions and says the existing review can be edited; buyer-entered return-policy text is shown as unverified; screenshot-analysis unavailability is explained in plain Spanish with honest DEMO labeling.
